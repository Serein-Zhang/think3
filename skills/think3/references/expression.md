# 表达参考

[返回复盘入口](../SKILL.md)

需要丰富复盘措辞时参考本页。这里的情境与短句提供语气方向，不是新增触发条件、必说台词或需要轮换的句库。普通纠错、首次合理失败和单纯进度询问仍按入口规则处理。

## 情境与措辞

先根据事实判断是否需要复盘，再自然组织语言。下表包含开场、过渡与复盘后的结论；例如“回看下来”须在实际检查后使用。示例中的错误、矛盾、进展或历史改进都需要本次材料支持，不能为了套用句子而虚构。

| 情境 | 表达示例 |
| --- | --- |
| 用户主动要求复盘 | 容我三省。 |
| 同一种方法反复失败 | 同一个地方又卡住了，三省一下。 |
| 两份证据互相矛盾 | 前后对不上，先三省一下。 |
| 发现自己的推理有跳步 | 这一步跨得太快，回头三省。 |
| 把结论说得过于确定 | 这话说满了，得回头核对。 |
| 关键反馈暴露了理解偏差 | 这里理解偏了，三省一下。 |
| 工作逐渐偏离原目标 | 走得有些远了，回到原题看看。 |
| 做了很多事，却没有实质进展 | 忙了一圈，得看看有没有走近目标。 |
| 持续增加投入，收益却不清楚 | 先三省一下，这一步还值不值得继续。 |
| 复盘发现原先的成功标准不够合适 | 做到这一步，得重新看看怎样才算做好。 |
| 新证据推翻了旧判断 | 新证据来了，旧判断得重新过一遍。 |
| 同一个问题再次出现 | 这个问题又出现了，得看看上次的改进落到了哪里。 |
| 一个阶段结束，需要总结 | 告一段落，回头三省。 |
| 阶段进展顺利，也值得总结经验 | 这次走得顺，也看看哪些做法值得留下。 |
| 复盘后发现当前方法仍然合适 | 回看下来，这条路可以继续走。 |
| 材料不足，复盘只能得到局部结论 | 先把能确认的说清，其余暂不下结论。 |

## 分寸与承接

以白话为主，“三省”本身已有文气；“吾”可偶尔点到，不必整段拟古。语气随用户语言、任务和沟通场合调整，严肃情境优先直接、准确，不强求趣味。复盘指向自身的理解、判断和行动，不训诫用户或表演自责。

通常一句开场即可。已经进入复盘时可以直接给发现，不再重复开场；不需要另说“三省完毕”或给一次检查增加仪式。并非每次都要出现“三省”，也不以用了哪个短句作为复盘完成的证据。

短句之后应接本次具体发现、关键依据和必要行动。以下均为假设场景，示范如何自然承接，不要求照抄或逐项展示：

> 这话说满了，得回头核对。目前只能确认文件生成，还没有实际运行的结果。

> 忙了一圈，得看看有没有走近目标。新增的几轮检索都在重复已有信息，下一步需要实际测试。

> 这个问题又出现了，得看看上次的改进落到了哪里。上次只更新了说明，实际检查步骤还没有改变。

## 较完整的复盘

“省所托、省所言、省所行”是较完整复盘的可选分项表达，可按实际内容组织：

- **省所托：** 是否围绕用户目标做事，实际结果与目标有什么差距？
- **省所言：** 哪些结论有依据，哪些仍是推测、未知或说得过满？
- **省所行：** 哪些经验已经落实，哪些仍待实施或验证；投入上值得保留、改变或停止什么？

它们是对本 Skill 检查角度的现代改写，并非古文原句。不要求凑齐三项或固定标题；即时纠偏直接说明相关的一点即可，仍须区分建议、已实施和已验证。
