# 跨项目检索与可选协作

## 先收窄问题

把“全面复盘”转成一个可回答的范围：时间段、交付阶段、反复出现的现象或待检验的方法。先看当前项目及已有记录，再查与机制直接相关的少量项目；必要时增加一个反例。不要因为有全库权限就读取不相关的个人材料。

找到现有聊天/项目工具后，先列出标题和摘要定位，再读实际消息及必要产物。索引摘要不等于已审阅聊天。可先读用户指令、纠正、最终回复和关键证据，遇到冲突才向前补时间线。保留原始标题和来源位置；不同版本或阶段的结果分开。

同一结论被多个摘要转述仍可能只有一个来源。跨聊天的一致意见也不替代实测；冲突先核对对象、版本、时间、条件和观测层级。历史记录只证明当时结果，状态容易变化时按当前任务需要做针对性核实。

## 沟通与文件所有权

用户已经允许跨聊天沟通时，可向实际负责人询问缺失证据、当前归属或交接状态。问题尽量具体：“记录 A 与 B 是否来自同一冻结版本？已有原始结果在哪？”先查可访问记录，避免让别人重复工作。

消息明确说明本次是复盘、需要的回复及操作边界。除非任务已授权恢复，不要求已停止专项继续实验。访问、沟通和修改/发布是不同范围；仅允许读取其他项目时，建议交回负责人处理。

本次用户授权不能作为可分享 skill 的永久全局许可。其他使用者与后续任务沿用其实际授权和权限。没有已知当前拥有者时查状态，而不是按旧聊天 ID 永久加锁或绕过锁。

## 复核与分工

先形成判断或改进提案，再用审阅视角检查。普通复盘可以由同一执行者分步骤完成；影响较大、证据冲突或难以自证时，才让独立审阅者介入。按需看四点：方案是否可行、是否覆盖目标、有哪些副作用或未知、投入是否与收益相称；无需给每次复盘额外设置审批。

审阅结论可为“当前范围内支持”“需修订”“证据不足”。需要修订时，说明哪条判断有问题、依据或证据缺口、最小修订或补证动作；没有实质问题就结束审阅。对新方法的事前审议与实施后的结果验收分开，不能靠提案通过、回复完成或任务勾选推定实际成果通过。

复核可按任务成本限制轮数和投入。达到上限、没有新增信息或补证条件不具备时，记录未决问题和重新判断的条件后结束本轮；不因“已经审了三轮”而强制通过，也不循环改写同一意见。

### 子智能体按需使用

简单复盘由当前执行者完成。材料较多、来源可独立核对或需要独立挑战结论时再拆分。以下任务书可复制；不固定模型、人数或专用工具，也不自动启动后台代理。

**证据整理者**

```text
复盘问题：【范围与时间】。
只读【项目/聊天/原始产物】，仅写【独占输出目录】。
输出关键目标、结果、纠正及对应证据位置，标明对象/版本/时间与缺口。
同时保留有效做法和反例；不要替主执行者编造根因，不操作应用、不重启旧专项。
材料已足以回答问题时停止扩查；说明实际读过什么和未读范围。
```

**独立审阅者**

```text
根据【原始需求与证据】评估【待判断的问题】。
只读来源，仅写【审阅目录】，不改变实现或运行状态。
检查结论是否受证据支持、是否混用时间/对象、是否遗漏合理替代解释。
指出哪些经验值得保留，哪些只适用于局部，什么额外信息会改变判断。
若评估改进方案，按需检查可行性、目标覆盖、副作用与成本。
给出当前范围内支持 / 需修订 / 证据不足；问题配具体证据缺口和最小补证或修订动作。
如无实质问题就说明范围，不为完成审阅制造批评或新规则。
```

独立前向验证只给请求、skill 和最小原始材料，不提前暗示预期结论；用于复杂 skill 或重要方法变化即可，不强制每次复盘都做。

**改进实施者（仅有相应授权时）**

```text
在【独占文件/候选目录】落实【有依据且已授权的改进】。
保持【用户设置/行为约束】，其他项目与应用只读。
执行与改动相关的验证；交付具体差异、结果、限制和恢复方法。
不扩大到【停止事项/相邻目标】，不自行安装或发布未授权变更。
```

主执行者汇总判断并检查适用范围；多个代理同意不等于证据充分。共享文件只有一个编辑者，真实应用/设备与最终部署由明确负责人统一操作。需要用户验证时集中提出有区分力的少量检查。

### 跟进而不重复派发

需要跨轮推进时，复用已有事项标识，记录负责人、建议/已实施/已验证/停止等状态、证据位置、阻碍及下一触发条件。分别写清本轮复盘是否结束和改进效果是否已有证据；“复盘结束，效果待下次实际使用验证”是合理终态。

已完成事项不因周期回顾或状态措辞含糊而重新执行；新证据、实际失败或用户需求变化才构成重评理由。已停止事项仍须遵守恢复授权。复盘发现未解问题，可以交付明确的缺口与交接，不为制造闭环擅自运行或改动。

## 记录与分享

在私人项目记录中保留可定位来源；分享 skill、模板或跨项目摘要时，只带必要的方法与匿名化例子，不附账号、凭证、私网端点、完整聊天或个人内容。原始历史保持原样，修正通过新说明和清晰的证据关联表达，避免把旧证据改写成新测试。

跟踪只需保存简短判断依据、证据链接、行动和可观察结果，不要求输出模型内部逐步推理。无需为复盘引入固定官职、全员会审、事件总线或持续后台调度。
