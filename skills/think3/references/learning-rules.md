# 经验如何沉淀、检验与撤回

用于复盘已有结果并选择实际改进。先保留有效做法，再处理失败与浪费；允许结论是“当前方法足够好，无需新增规则”。

## 区分四种状态

| 状态 | 应写什么 | 不能越过的边界 |
|---|---|---|
| 事实 | 在什么对象、版本、条件下观察到什么；链接原始结果、反馈或产物 | 多份转述不等于多个独立观察；记录“发生过”不等于解释了原因。 |
| 因果假设 | 哪个机制可能解释差异，其他解释是什么，什么证据能区分它们 | 先后顺序、相关性、一次成功或一次失败不能独自证明因果。 |
| 候选经验 | 下次遇到哪些条件，尝试改变什么；预期收益与可能代价 | 保留为有待检验的做法，不写成所有项目的强制规则。 |
| 有范围的实践 | 支持它的证据、适用前提、例外、实际效果和失效信号 | 验证充分也不代表跨软件、设备、受众、任务或时期自动成立。 |

这些状态帮助表达认识，不要求每条经验机械走完四步。单次问题若后果严重、机制明确且修复可验证，可以立即改正；不必等它再次发生。
重复出现也要核对独立性：同一个日志被多人引用、相同环境被反复测试，可能仍只有一份证据。避免从次数直接推导普遍性。
评价当时决策时，区分“当时可获得的信息”和“事后才知道的信息”；不要用后见之明把合理探索都写成失误。

## 决定是否值得保留

保留带来实际收益的方法，包括恰当的简化、主动停止、有效分工、用户喜欢的表达和避免了返工的检查。写清它为何适合本次目标。
对失败，先区分需求变化、合理试验失败、实现缺陷、沟通误差、外部限制与判断失误；不要把它们都归为“以后更谨慎”。
只有能改变下一次行动的认识才值得固化。收益可能是更少误判、更快定位、更低负担、较好作品或更易恢复；不强迫所有收益量化。
需要判断目标或标准本身是否有问题时，提出替代假设及其代价；用户目标的改变仍由用户决定。
新规则的维护、阅读、执行与误阻拦成本也计入代价。能删掉冗余步骤或缩短规则时，优先做减法。

## 选择最小的沉淀位置

| 落点 | 适合什么 | 保持什么边界 |
|---|---|---|
| 当前回复或交接 | 一次性的事实、待核对事项、下一步与停止事项 | 不必为了留痕另造长期文档。 |
| 项目说明或约定 | 特定项目的入口、职责、环境要求与已确认偏好 | 写明范围；项目惯例不自动成为所有项目规则。 |
| 测试或验证步骤 | 可稳定观察、会实际影响结果的回归风险 | 模拟、软件、实体与最终产物分别验收；不为简单改动添加同义测试。 |
| 代码或配置 | 已定位的问题可由实现直接消除 | 做最小相关改动，保留用户设置与恢复方法。 |
| 工具或模板 | 重复且确定的步骤值得自动化，或统一格式能减少实际错误 | 显式输入与适用条件；工具输出不超出它真正检查的范围。 |
| Skill | 可迁移的判断流程、非显然约束和按需使用的资源 | 写给下一位执行者，保持入口精简；案例放参考，不逐次追加禁令。 |
| 记忆 | 用户明确要求长期记住的偏好或可复用事实 | 未明确要求更新记忆，不写 memories；获授权后遵循当前环境的记忆写入规则。 |

先检查已有落点，避免同一规则散落多份、互相过期。现有规则冲突时定位其来源、范围和新旧证据，不简单采用篇幅更长或措辞更强的一方。
在当前任务已有授权内，可直接完成必要的最小可逆改进并验证；复盘发现的跨项目改造、外部发布或其他超出范围的动作先列为建议。
创建或调用本 skill 不自动授权永久修改其他 skill、项目约定或记忆，也不自动创建后台定期任务。用户要求的具体改进仍应按原授权执行，无需重复确认。

## 给改进一个可结束的闭环

每项选中的改进按需要记录：改变什么、适用条件、依据、执行者或接续位置、成功信号、下次检查触发点、撤回或缩小范围的条件。
状态用“建议／已实施待验证／已验证于指定范围／已撤回或替换”等明确表述；写下建议或完成修改都不等于效果已经验证。
下次检查可以由下一次交付、同类操作、环境变化或用户选定周期触发；没有触发就不伪造结论，也不为了复盘反复执行生产动作。
若错误未减少、负担明显增加、前提改变或出现反例，检查原因并删减、替换或撤回规则；保留必要的历史依据，停止把旧结论当当前事实。
当本次已有足够证据支持决定、关键未知和下一步已交接，就结束复盘。只有新的结果或具体矛盾才开启下一轮，不继续复盘“复盘写得是否够完整”。

## 两个简短示例

**发布案例（假设情景）**：下载包含旧组件是事实；“构建入口引用旧路径”起初是因果假设。定位并验证后，可立即修正该入口，再增加能检出旧组件的检查。实践限于具有同类嵌套产物的发布链，不要求所有文档导出都执行同样检查。

**创作案例（假设情景）**：一次访谈剪辑采用更长停顿，获得受众认可。保留“该题材与表达目标下，停顿增强了情绪”的候选经验；在相似片段继续对照观察。短促信息片若出现理解或节奏损失，就缩小适用范围，不把“所有视频都应放慢”写入通用模板。
