# 吾日三省吾身

正式调用：`$think3`。`think*3` 是自然语言简称，不是额外注册的调用标识。

让下一次工作得到改善。以三个工作问题组织反思：**目标与结果是否一致？判断与证据是否相称？投入与沉淀是否值得？** 这是本 skill 的工作框架；名称不代表每天固定执行三次，也不自动建立定时任务。

## 选合适的复盘尺度

- **即时反思**：遇到重复失败、重要用户纠正、意外成功或证据冲突，短暂检查一个关键假设；有明确下一步后继续已授权工作。
- **阶段复盘**：一个可交付版本、实验或创作阶段结束，需要总结方法时，比较目标、成果和代价，选出最有价值的保留/改变/停止事项。
- **周期回顾**：用户指定日、周或其他周期时，主要读上次复盘后新增的结果；没有新证据可以明确“维持现有方法”，不强行制造改进。
- **跨项目归纳**：怀疑同一机制在多个项目重复出现时，抽样相关案例和反例，再限定可迁移的条件。访问范围大不意味着必须扫描全部聊天。

小任务用几句话即可；完整复盘按需要读下面的参考。用户仅问状态时先回答状态，不自动变成长篇反思。需要后台周期执行时，只有用户明确要求安排并给出或确认所需日程后才创建自动化；普通复盘和本 skill 创建不作此推断。

## 取证与协作

先读取当前用户目标、项目入口/状态、最近反馈、实际产物及已有复盘；记录本次范围、对象/版本和截止时间。历史总结用于定位，关键冲突回到原始消息、文件或可观察结果。保留当时掌握的信息，避免用事后结果苛责当时合理的选择。

跨项目或跨聊天时读 [范围、检索与协作](references/cross-project-review.md)。已有授权内可读取相关上下文、联系负责聊天，不反复请求同一授权；授权沟通不自动授权重新启动已停止工作、改动其他项目或部署。没有权限/工具时明确证据缺口，不假装读过。

## 三省

### 一省：目标与结果

说明用户原本要什么、后来如何调整范围，实际获得了什么。区分完成、部分完成、失败、未验证和已停止。把正确做法与失败一起复盘；文件生成、部署、运行、实体效果或最终交付分别看其对应证据，不按动作数、测试数或投入时长判定成功。

问：**成果解决了真实需要吗？哪些结果值得保留？差距确实存在，还是我们用了不合适的标准？**

### 二省：判断与证据

把重要说法标清为观察事实、解释/推断或尚待验证的假设。对于差距，找出当时依赖的前提、替代解释、反例，以及能区分解释的最小检查。不要强求一个根因；证据不足就保留未知。

审视两层改进：一层是把已有方法做得更好；另一层是检查目标、假设、证据标准或方法选择是否应改变。也检查旧的否定结论是否已被新证据推翻，及时撤回失效结论；版本/环境不同的有效历史结果不一并抹去。

重要改进或存在证据冲突时，按 [复核与分工](references/cross-project-review.md) 检查可行性、目标覆盖、风险和成本；必要时独立审阅。意见须指出具体问题、缺少的证据和最小修订/补证动作。方案审议通过不代表实施效果已验证；复核达到投入上限也不能强制通过。

问：**我们为什么这样判断？什么信息会使这个判断改变？下一步检查真的能区分原因吗？**

### 三省：成本与沉淀

检查有无重复检索、重复验证、过度并行、无收益等待、过早扩功能或增加流程。记录停止某条研究、保留现状、撤掉无效规则同样可以是正确改进。估计成本时注明依据，不虚构节省时间或成功率。

按 [经验晋升与撤回](references/learning-rules.md) 决定落点：本次备注、项目说明、代码/测试、可复用工具、领域 skill，或需要明确请求才更新的长期记忆。单个案例可以支持窄范围修复，不自动变成所有项目的规则；重复次数本身也不能证明因果或通用性。

问：**下次具体保留、改变或停止什么？适用条件是什么？如何知道改进有效，又何时撤回？**

## 落实与输出

通常选择最重要的一至三项改进，不强制凑数。每项写清：依据、具体改变、适用范围、负责人/执行位置、状态、下一次验证机会与成功或撤销条件。建议、已实施、已验证分开。

跨轮跟进时沿用同一事项标识，区分“本轮复盘已收口”和“改进仍待验证”。没有新证据、失败或范围变化，不重复派发已完成事项；停止事项只有获得相应恢复授权后才重启。简单任务不必为此建立看板或新增系统。

用户只要求总结时交付结论和建议；已有修复/优化授权时，落实范围内最小有用的改进并验证，不在建议处停下。后续跨项目修改遵守现有所有权与范围。仅需澄清实际缺失信息或权限，不为复盘额外设置审批。

默认在聊天交付与问题相称的复盘；需要持久记录时沿用项目既有位置和约定。可选 [复盘模板](assets/retrospective.md) 或 [经验卡](assets/learning-card.md)，简单问题不强制生成文件。案例迁移可读 [跨领域样本](references/transfer-examples.md)。

完成条件：关键差距或有效做法有依据，下一步具体可行，已授权的本轮改进已处理，未知有边界。新增阅读已不改变结论、行动或验证方式时停止扩查。不为了写出更长的复盘再次复盘，也不自动等待未来验证；把后续触发条件交接清楚。

后续再次使用时先检查上次改进是否产生效果，保留有效项、调整无效项、撤回过时项。最终看同类错误、定位成本或任务质量是否改善，而不以复盘次数和规则数量评价成果。
