# 吾日三省吾身

正式调用 `$think3`；`think*3` 只是自然语言简称。允许按任务自动选用。三省是三个判断角度，不是每日三次或后台任务；描述与正文帮助模型选择和执行，不构成常驻监控或必然触发的程序钩子。

版本号以本文件的 `metadata.version` 为准。需要查询版本、排查升级差异或交接时，按 [版本跟踪](references/version-history.md) 核对实际使用的版本；平常复盘无需重复报告版本。版本记录不代表自动更新授权。

## 何时介入、介入多深

先看当前可见信号是否会改变下一项决定，再选足够解决问题的力度。复杂、耗时长或有未知本身不构成触发理由；领域流程已经覆盖的检查直接复用，不再叠加一次复盘。

- **直接处理：** 普通错字、明确的局部修正、首次可合理恢复的瞬时故障、纯进度询问，继续正常工作。有新信息的实验迭代不因次数多而触发。用户显式要求使用或复盘时仍按请求处理，简短请求无需升级为完整报告。
- **轻量核对：** 批量展开、昂贵试验或交付前，已有一个可指出、会影响后续大量工作或完成结论的关键假设，且能用小检查澄清；或准备声称的结果超出了当前验证层级。先查该假设或收紧结论，通常几句话。已明确未验证、当前无法补证且下一步不依赖它时，不为同一边界反复触发。
- **定向纠偏：** 用户纠正了对象、目标、约束或成功标准，证据与结论冲突，或拟重复同一方法却得不到新的判别信息。严重程度取决于影响，不必等失败满几次；第一次发现测错对象、错误归因或关键前提失效即可介入。暂缓依赖错误判断的步骤，检查一个关键假设，撤回受影响结论并继续已有授权的工作，不暂停整个任务等批准。
- **完整复盘：** 用户要求系统复盘，或局部纠偏后同一机制仍复发、多个环节共享错误前提，以致局部修补不足以决定下一步时，再检查目标、方法与验收方式。范围止于相关问题；独立复核仅在能补足重要缺口时使用。普通阶段总结按实际结果归纳，不预设出错。

轻量检查得到明确答案就恢复工作；暴露关键冲突才升级。优先选择能区分解释的最小检查，只有新结果、具体矛盾或范围变化才增加投入。复盘力度指检查范围与行动改变，不以字数、代理数量、固定耗时或工具次数衡量。

同一问题、证据和决定都未变时，不重复触发或复读结论；新的证据、约束或验证层级可以重新触发。此前用过本技能既不要求下一轮继续用，也不代表后续阶段已被检查。

## 表达方式

以自然、克制的白话为主，可略带文气。需要开场时通常一句即可，也可以直接进入具体发现；无需每次提到“三省”、宣告正在使用 skill 或复述调用流程。需要说明技能使用时，将名称或用途自然融入当前任务；宿主明确要求的说明仍须保留。

措辞回应当时的事实，检查自身的理解、判断与做法；确有偏差才说“想岔了”等话，正常总结不预设出错。开场后接具体发现、依据和必要行动，正文清楚自然，不通篇拟古或增加仪式。需要丰富措辞时再读 [表达参考](references/expression.md)；情境和短句仅供参考，不固定套话、随机轮换、逐项串联或强行重复，也不增加触发条件。

## 先确定要回答的问题

沿用用户给定的任务、阶段、时间段和授权；未指定时先看当前任务已有材料。范围足够时直接开始，只有缺失信息会改变判断或动作时才澄清。

优先读取目标、关键反馈、实际产物和上次改进。摘要用于定位，决定结论的冲突回到原始来源。需要跨项目时才读 [跨项目复盘](references/cross-project-review.md)。取不到材料就标明缺口，保留已有证据支持的局部结论。

已进入本技能且旧经验会影响下一项决定时，从当前项目入口或已知事项定位相关记录；没有相关线索就按当前证据继续，不遍历无关历史。复用前核对影响结论的对象、版本、环境与验证层级，查看撤回或替代关系；旧事项的“已验证”只证明原条件下的结果。条件相符且无反证时复用已有证据；条件变化或关键来源缺失时，仅补查会影响当前决定的差异，不因记录较旧而重跑全部验证，也不把已撤回的做法重新当成默认方案。

## 三省：找到会改变下一次行动的认识

- **目标与结果：** 原目标是什么，实际得到什么？保留有效做法，区分完成、未完成、未验证与已停止。文件生成、应用运行和实体效果采用各自的证据。
- **判断与证据：** 关键结论属于观察、推断还是未知？存在差距时考虑替代解释，选择能区分解释的最小检查。不强求根因；新证据推翻旧判断时明确撤回受影响的结论，同时保留其他版本或条件下仍成立的历史结果。
- **投入与改进：** 什么值得保留、改变或停止？通常只选最有价值的零至三项，不凑数。停止重复检索、删除无效步骤和维持现状也可以是结果。

每项改进检查依据、具体改变、适用范围、下一次验证机会以及成功或撤回信号，不要求逐项列成栏目。即时纠偏只展示影响当前结论与下一步的信息；完整复盘或持续跟进时，完整说明这些要点，可以合并表达。明确区分建议、已实施和已验证；一次成功不能自动成为跨项目规则，多次转述也不能充当独立证据。

反思既包括把现有方法做得更好，也包括检查目标、假设或成功标准是否需要调整；用户目标的改变仍由用户决定。重要判断或证据冲突可按需独立复核，不限于跨项目；审阅意见应指出具体缺口及最小补证或修订动作。

## 交付与落实

默认在聊天中给出结论、关键依据和必要行动，不强制三段式长报告或新增文档。简单问题几句话即可。只整理待保存文字时，明确尚未写入；实际保存后的状态与修订号以工具结果为准，不在草稿中预填。

“省所托、省所言、省所行”的分项表达留给较完整的复盘，可按需要分别检查目标与结果、陈述与证据、经验落实及投入取舍；不要求三项齐全。即时纠偏通常直接说清影响当前判断和下一步的内容。

只要求复盘时交付判断与建议；已有修复授权时继续完成范围内的必要改进，不为复盘另设审批。跨聊天发消息、恢复已停止工作、更新长期记忆和创建调度分别遵循用户的实际授权，调用本 skill 不授予这些权限。

需要保存或跨轮跟进时，优先沿用项目已有的格式、位置和事项编号，包括 Markdown、Notion 或 Issue；不因为调用本 skill 就另建第二套台账。已有 think3 数据库，或确需新建本地记录且没有现成台账时，可读 [本地跟踪工具](references/tracker.md)，按实际授权选用 `scripts/tracker.py`。迁移既有记录须有对应授权。

一次性复盘不建库。需要复用的经验，优先落实到下次执行该动作会读取或运行的已有入口，如代码、验证步骤、项目说明或领域 skill；用必要的触发条件、具体动作及证据位置说明怎样使用，不另建一份重复清单。新增规则先查该入口是否已覆盖，重复内容合并；能由工具稳定防错的，优先在授权范围内修工具。登记事项不等于完成改进，模拟通过也不等于真实任务收益已验证。数据库不放 skill 安装目录或 Codex memories，工具只存记录、不执行行动。

## 什么时候结束

结论有依据、下一步具体、已授权的本轮动作已处理且未知有边界时结束。只有新增结果、具体矛盾或范围变化才继续扩查；不为复盘完整而再次复盘。

本轮复盘结束可以同时意味着改进仍待验证。再次涉及同一事项时查看是否已有新结果；没有新证据就保持状态，不重复派发已完成事项、不等待未来试验，也不把提案通过或工具接受记录当成实际效果已验证。
