# 持续维护

主维护对话与 Codex 项目绑定正式仓库，代码修改使用该对话关联的维护工作树。开始时核对实际根目录、分支、Git 状态及本机 `.maintenance/` 中的维护状态，不沿用已经失效的工作目录假设。

## 检查与行动

定期检查本地源码版本、安装版、GitHub 默认分支与最新 Release 是否一致，查看新的相关反馈、未提交改动与待验证事项。没有新证据或改动时，只更新简短检查状态；不要重复运行整套测试、重新打包同一版本或重读全部历史。

发现问题时先确认影响范围与证据，在已有维护授权内完成必要修复与检查。自动化不清理他人修改，不自动合并冲突，不替其他项目执行记录中的动作，也不将历史模拟结果视为本次真实效果。

运行文件发生变化时更新 Skill 版本与随包记录，执行完整 CLI 测试、构建检查、归档运行检查及可用的技能格式校验，核对安装包与源码。发布使用新的提交、标签和 Release，保留实际时间、原始文件与 SHA-256，再读取远端结果确认。文档与项目组织变化单独提交，不增加运行版本。

## 对话与本机记录

开发、审查、安装、版本迭代与发布对话归入本项目。其他领域任务中偶尔调用 think3 的对话保留原项目，仅在确有维护价值时记录相关出处。

迁入的历史对话可能保留原始执行目录，部分 macOS 记录的运行路径不能在 Windows 上恢复。它们作为历史依据保留；后续维护从当前正式仓库和关联工作树继续，不为整理项目而自动重启历史任务。

完整私人对话索引、原项目归属、移动回执、自动化标识及最近检查结果保存在主工作目录 `.maintenance/`，不复制到工作树、不提交 Git，也不进入发布包。该目录中的旧状态只用于定位；当前 Git 和实际工具回读优先。

## 定期检查的边界

每小时检查由 Codex 的本地定期任务执行，依赖本机与客户端具备运行条件。它不是秒级文件监控；首次计划运行的结果与任务创建成功分别记录。没有新问题时无需主动发送额外消息。
